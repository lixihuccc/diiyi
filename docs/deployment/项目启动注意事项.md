## 2. 一键启动（推荐）

在项目根目录双击：

```text
start.bat
```

脚本会依次完成：

1. 检测 Python（优先 `py -3.13`，其次 `python`，最后 `py -3`）。
2. 校验 `.venv` 是否真的可用；不可用则删除并重建。
3. 校验后端依赖，缺失时执行 `pip install -r requirements.txt`。
4. 执行 `bootstrap_db.py`：建库 / 灌演示数据 / 对齐 Alembic 迁移版本。
5. 校验前端依赖，缺失时在 `app/` 下执行 `npm.cmd install`。
6. 分别在新窗口启动后端（8080）和前端（5173）。
7. 轮询等待两个服务就绪，然后自动打开浏览器。

### 启动后的访问地址

| 服务 | 地址 |
|------|------|
| 前端页面 | <http://localhost:5173> |
| 后端 API | <http://localhost:8080> |
| Swagger 文档 | <http://localhost:8080/docs> |
| 健康检查 | <http://localhost:8080/health> |

默认管理员账号：

```text
用户名：admin
密码：123456
```

> 登录页需要输入图形验证码，验证码由后端生成并保存在 `fakeredis` 中。

## 4. 手动启动（排查时使用）

### 4.1 后端

在项目根目录执行：

```bat
.venv\Scripts\python.exe -m uvicorn src.main:app --host 127.0.0.1 --port 8080
```

### 4.2 前端

在 `app` 目录执行（注意必须用 `npm.cmd`）：

```bat
npm.cmd run dev
```

### 4.3 数据库

```bat
.venv\Scripts\python.exe bootstrap_db.py
```

`bootstrap_db.py` 会处理四种情况：

- 数据库不存在 → 建表 + 写入演示数据 + 标记迁移版本；
- 缺少 `alembic_version` 表 → 标记为最新；
- 迁移落后 → 执行 `alembic upgrade head`；
- 迁移失败（脏状态）→ 把旧库备份为 `chenguang.db.bak_<时间戳>` 后重建。

手动执行迁移：

```bat
.venv\Scripts\python.exe -m alembic upgrade head
```

## 5. 常见问题排查

### 5.1 双击 `start.bat` 后闪退

在 CMD 中运行以查看完整报错：

```bat
cd /d 项目根目录
start.bat
```

常见原因：Python 未安装、`requirements.txt` 缺失、`npm.cmd` 不在 PATH。

### 5.2 `.venv` 无法使用

典型报错：

```text
did not find executable at 'C:\Users\xxx\...\python.exe'
```

原因：虚拟环境是从别的电脑拷贝来的，`pyvenv.cfg` 里的 `home` 指向了不存在的路径。

处理：删除 `.venv` 后重新运行 `start.bat`，脚本会自动重建。

```bat
rmdir /s /q .venv
start.bat
```

> 不要把 `.venv` 提交到 git，也不要在多台机器之间复制。

### 5.3 pip 安装慢或失败

切换国内镜像：

```bat
.venv\Scripts\python.exe -m pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 5.4 端口被占用

默认端口：后端 `8080`，前端 `5173`。

```bat
netstat -ano | findstr :8080
netstat -ano | findstr :5173
```

找到 PID 后结束进程，或关闭对应窗口。`start.bat` 检测到端口被占用时会跳过启动，不会重复拉起服务。

### 5.5 后端启动日志出现 MinIO 连接失败

日志类似：

```text
minio 桶创建失败：... [WinError 10061] 目标计算机积极拒绝
```

- 这是**预期现象**：本机未启动 MinIO，后端会记录错误但继续启动。
- 代价是启动阶段会重试约 20 秒，`wait_ready.py` 的最长等待时间是 120 秒，足够。
- 影响范围：知识库文件上传 / 下载不可用；登录、列表、增删改查不受影响。
- 如需使用文件功能，启动 MinIO：

```bat
docker compose -f docker/docker-compose.yaml up -d
```

并将 `.env` 中的 `MINIO_ENDPOINT` 指向 `127.0.0.1:9000`。

### 5.6 前端页面空白 / 请求跨域失败

- 请使用 <http://localhost:5173> 访问，**不要用** `http://127.0.0.1:5173`。
  后端 CORS 白名单只放行了 `http://localhost:5173` 和 `http://localhost:3000`。
- 检查 `app/.env.local`：

```ini
VITE_USE_MOCK=false
VITE_API_BASE=http://localhost:8080/api/v1
```

- 如果只想看前端、不启动后端，可临时改成：

```ini
VITE_USE_MOCK=true
```

### 5.7 登录提示“验证码错误 / 已过期”

- 验证码有效期 5 分钟，保存在 `fakeredis` 内存中。
- 后端重启后旧的验证码会全部失效，刷新登录页重新获取即可。
- 点击验证码图片可刷新。

### 5.8 `npm.ps1` 被执行策略拦截

本机 PowerShell 执行策略会拦截 `npm.ps1`，请统一使用：

```bat
npm.cmd install
npm.cmd run dev
```

### 5.9 `start.bat` 修改后出现乱码或语法错误

`start.bat` 必须保持：

- **GBK 编码**；
- **CRLF 换行**。

CMD 在 `chcp 65001` 下读取 UTF-8 批处理会出现文件指针错乱；纯 LF 换行会拆断 `if` / `for` 等复合语句。
若用 VS Code 修改，请用“通过编码保存 → GBK”，并确认换行符为 CRLF。

## 6. 验证启动是否成功

```bat
curl http://localhost:8080/health
```


```bat
curl -o nul -w "%{http_code}" http://localhost:5173/
```

期望返回 `200`。

最后打开 <http://localhost:5173>，使用 `admin / 123456` 登录。

## 9. 安全提醒

- `.env`、`.venv`、`chenguang.db`、`node_modules`、日志等不应提交到 git。
- `src/utils/jwt_utils.py` 中的 `SECRET_KEY` 当前是硬编码的示例值，生产环境必须改为环境变量。
- 默认密码 `123456` 仅用于本地演示，部署前必须修改。
- `fakeredis` 与 SQLite 仅适用于本地开发；生产环境请切换 MySQL / Redis / MinIO。

## 10. 脚本职责速查

| 文件 | 作用 |
|------|------|
| `start.bat` | 一键启动入口（GBK + CRLF） |
| `bootstrap_db.py` | 数据库引导：建库、演示数据、迁移升级、异常备份重建 |
| `wait_ready.py` | 轮询等待前后端就绪 |
| `init_data.py` | 建表并写入演示数据（幂等） |
| `requirements.txt` | 后端依赖清单（UTF-8） |
| `app/.env.local` | 前端 API 地址与 Mock 开关 |
