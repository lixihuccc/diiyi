## 一、设计目标与范围

### 1.1 要解决的问题

V2 的核心不是「多做几个管理页面」，而是让原本只存在于数据库里的角色与权限数据，变成用户能感知、评审能验证的访问边界。原型的任务因此有三条：

1. **让边界可见**：用户随时知道自己是谁、数据范围多大、当前页面需要什么权限码。
2. **让拒绝有因**：被隐藏或禁用的操作必须说明缺的是功能权限，还是数据归属，对应哪个业务码。
3. **让评审可走通**：同一个页面能切换三种身份，直观看到菜单、按钮、数据行如何一起变化。

### 1.2 覆盖范围

| 覆盖 | 说明 |
|---|---|
| 功能权限的界面呈现 | 菜单过滤、路由守卫、按钮显隐与禁用 |
| 数据权限的界面呈现 | 列表过滤、归属人标识、可见范围、数据级拒绝 |
| 授权管理主流程 | 用户分配角色、角色配置数据范围与权限、权限码维护、授权审计 |
| 异常与边界 | 40300 / 40301 / 40302 / 40303 / 40901 / 40902 的界面形态 |
| 响应式与可访问性 | 1440 桌面与 390 移动端；键盘焦点、减少动效 |

### 1.3 不覆盖

- 模型、Prompt、知识库、工具、对话日志、数据统计的完整业务页面。它们保留在菜单中，标注「原型」并提示不在本次范围，用于验证菜单过滤逻辑。
- 后端鉴权、缓存失效、数据库迁移等实现细节。
- 真实登录、真实数据与接口联调；原型数据全部为前端 mock。

## 二、设计概念：授权台账（The Clearance Ledger）

### 2.1 三条命题

**边界可见。** 每个业务页面顶部有一条分级授权条（boundary strip），持续显示当前身份、数据范围、功能权限概况与本页所需权限码。它借用了涉密文档的分级标识形式，但表达的是产品事实，不是装饰。

**拒绝有因。** 详情页右侧设置「权限注记」，逐条说明可查看、可编辑、可删除、可发布的判定依据；列表页在底部解释「公开 ≠ 可编辑」。禁用的按钮保留在界面中并给出原因，而不是悄悄消失，让用户能区分「我没有这个功能权限」与「这条数据不归我」。

**线条叙事。** 信息用规则线、留白与对齐组织，而不是把每块内容装进相同的圆角卡片。表格是台账，不是卡片列表；分隔线承担层级，阴影几乎不出现。

### 2.2 与通用后台的差异

| 常见默认 | 本原型的选择 | 理由 |
|---|---|---|
| 四张统计卡作为首屏 | 首屏是「我的授权范围」台账 | 授权原型的首屏应先回答「我能看到什么」，而不是「平台有多大」 |
| 菜单置灰表示无权限 | 无权限菜单不渲染 | 与 PRD 6.2 一致，也避免用户反复点击失败 |
| 权限失败只弹一句 toast | 就地注记 + 业务码 + 规则说明 | 内部平台优先可排查性 |
| 所有内容装进同一种圆角卡片 | 带线表格 + 少量注记块 | 让层级来自结构，而不是统一的投影 |
| 装饰性渐变与图标堆叠 | 单一权威色 + 权限码作为证据 | 色彩只承载「允许 / 拒绝」两类语义 |

## 三、设计系统

### 3.1 颜色

| Token | 色值 | 用途 | 说明 |
|---|---|---|---|
| 骨白 | `#EFEEE8` | 应用画布 | 冷调纸色，避免暖米色 + 陶土色的常见组合 |
| 纸白 | `#FAFAF6` | 内容面、表格 | 与画布形成轻微层次，不使用阴影 |
| 墨黑 | `#151B19` | 侧栏、主文字 | 带极轻绿调，与松绿同族 |
| 石墨 | `#5E6763` | 次级文字、表头 | 在纸白上对比度约 5.6:1 |
| 规则灰 | `#D8D6CC` | 分隔线 | 结构线，不承担强调 |
| 松绿 | `#1E5B49` | 授权、主操作、当前态 | 权威色，只用于「允许 / 主行动」 |
| 印红 | `#A23B2B` | 拒绝、危险操作、403 | 只用于否定语义 |
| 砂色 | `#E8E3D3` | 分级条、注记底 | 提示性底色，不用于大面积装饰 |

使用约束：

- 松绿和印红不互换语义；删除按钮在无权限时退为中性灰，而不是继续显示红色。
- 状态色同时配有文字（运行中、已停止、异常），不单独依赖颜色。
- 表头与次级文字统一使用石墨，避免出现第四种灰。

### 3.2 字体

| 字体 | 角色 | 字号与字重 |
|---|---|---|
| Noto Serif SC | 页面标题、角色名、错误页标题、品牌 | 30 / 27 / 21 / 20 / 18 px，600 |
| IBM Plex Sans SC | 正文、表格、按钮、表单 | 15 px 正文；13.5 px 表格；12.5 px 辅助；11.5 px 标签；400 / 500 / 600 |
| IBM Plex Mono | 权限码、资源 ID、时间、数字 | 11–13 px，400 / 500，启用 tabular-nums |

排版规则：

- 正文行长控制在 68 字符以内；表格内数字右对齐。
- 权限码、用户 ID、时间这类「字面值」使用等宽字体，属于功能需要，不用作装饰性小标签。
- 不使用全大写英文标签、单词级高亮、标题上方的装饰性眉标。
- 中文标题使用宋体形成文档感，正文使用无衬线保证扫读效率；两者职责清晰，不混用。

### 3.3 布局与网格

- 桌面侧栏 232 px，顶栏 56 px，分级授权条 36 px；内容区左右内边距 32 px，最大宽度 1240 px。
- 表格不放进卡片；表头下使用 1 px 深规则线，行间使用 1 px 浅规则线。首列不缩进，操作列右对齐。
- 控件圆角统一为 2 px；除身份切换菜单与弹窗外不使用投影。
- 内容以左对齐为主；数字列右对齐；操作列右对齐。没有居中的正文段落。

## 四、核心组件规范

### 4.1 分级授权条（Boundary strip）

位置固定在顶栏上方，所有登录后的业务页面共用。

| 区域 | 内容 | 说明 |
|---|---|---|
| 标识 | 授权边界 | 松绿底，表示这是一个持续的访问状态 |
| 身份 | 姓名 / 角色 | 与右上角预览身份一致 |
| 数据范围 | 全部数据 / 仅本人数据 | 直接对应 `roles.data_scope` |
| 功能权限 | 全局通配 / N 个模块通配 + M 项精确 | 让评审看到权限来源形态 |
| 本页状态 | 本页需要 `code` 已授予 / 未授予 / 登录即可访问 | 路由级权限的可视化 |

- 移动端换行显示，页面所需权限单独占一行，不隐藏在横向滚动里。
- 身份切换后，分级授权条会做一次 0.7 s 的底色回落，提示「边界刚刚变化」；`prefers-reduced-motion` 下取消。

### 4.2 权限注记（Access notes）

用于详情页与需要解释的区块，固定 300 px 宽，主内容在左。

结构：

1. **事实**：归属人、可见范围、当前数据范围、当前角色。
2. **判定**：可查看 / 可编辑 / 可删除 / 可发布，每行一个 `✓` 或 `×`，后接原因。
3. **规则脚注**：说明两层权限是 AND 关系。
4. **可执行动作**：只有可写时才出现的「修改可见范围」。

文案规则：

| 场景 | 文案 | 业务码 |
|---|---|---|
| 缺功能权限 | 缺少 agent:update | 40300 |
| 有功能权限但非归属人 | 只有创建者可以删除 | 40302 |
| 私有资源且无数据范围 | 资源为他人私有，不在你的可见范围内 | 40301 |
| 越权授权 | 不能授予自己没有的权限 | 40303 |

### 4.3 权限门控的三种形态

| 形态 | 适用 | 示例 | 依据 |
|---|---|---|---|
| 不渲染 | 菜单、页面级新建入口、区块 | 无 `user:list` 时侧栏没有用户管理；无 `agent:create` 时不渲染新建按钮 | 6.2 / 6.4 / C-02 |
| 渲染但禁用 | 数据级写操作 | 有 `agent:update` 但资源不归自己：编辑按钮禁用，title 说明 40302 | 6.4 / C-04 |
| 路由守卫 | 直接输入 URL | 无 `role:list` 访问 `roles.html` 跳转 403 页面 | 6.3 / C-03 |

原则：**功能权限缺失 → 入口不出现；数据权限不足 → 入口保留并解释**。前者是角色能力问题，后者是记录归属问题，混在一起会让用户误以为界面坏了。

### 4.4 预览身份（原型评审控件）

- 位于顶栏右侧，虚线边框 + 「预览身份」标签，明确区别于产品功能。
- 三个身份：周正（超级管理员）、林晓（运营人员）、陈默（只读访客）。
- 切换后写入 URL 的 `role` 参数，菜单、按钮、数据行、注记同步变化；所有页面链接保留该参数。
- 仅用于评审，不模拟真实登录；产品实现中身份来自 `/users/me`，权限不写入 `localStorage`。

### 4.5 错误与空状态

| 业务码 | 页面表现 | 退出路径 |
|---|---|---|
| 40100 / 40101 | 真实产品跳转登录页；原型不模拟 | — |
| 40300 | 独立 403 页面，显示请求路径、所需权限码、当前身份 | 返回工作台 / 返回上一页 |
| 40301 | 页面内替换为「不在可见范围内」，保留导航 | 返回列表 / 切换身份 |
| 40302 | 按钮禁用 + 权限注记说明 | 留在当前页 |
| 40303 | 授权弹窗内提示，指出被拒绝的权限码 | 调整勾选 |
| 40901 / 40902 | 删除按钮禁用 + 关联数量 | 留在当前页 |

列表空状态统一为「暂无可访问的数据」，并区分「确实没有数据」与「没有权限」；原型中通过数据权限过滤后的 0 条来体现。

### 4.6 动效与反馈

- 没有页面加载动画、逐区块淡入、卡片悬停上浮。
- 动效只回应用户动作：身份切换的边界提示、弹窗开合、菜单展开、保存后的 toast。
- 所有动效在 `prefers-reduced-motion: reduce` 下关闭。

### 4.7 可访问性

- 全站可见的键盘焦点环（2 px 松绿，偏移 2 px）。
- 跳转主内容的 skip link；侧栏 `aria-label`；当前菜单项 `aria-current="page"`。
- 身份切换为 `aria-expanded` + `role="menuitemradio"`；ESC 关闭，点击外部关闭。
- 弹窗 `role="dialog"` + `aria-modal`；ESC 关闭；打开时聚焦首个控件。
- 表格使用真实 `<table>` / `<th>` / `<caption>`；移动端隐藏 caption 时，关键信息已移入工具条文案。
- 颜色对比：正文与次级文字均达到 WCAG AA；状态不只靠颜色区分。

### 4.8 响应式

| 断点 | 行为 |
|---|---|
| > 1180 px | 授权范围三栏；详情页主区 + 300 px 注记 |
| ≤ 1024 px | 侧栏抽屉化；详情注记移到主内容上方；登录页单栏 |
| ≤ 760 px | 分级条换行；页面操作按钮左对齐；授权范围单栏；表格横向滚动并显示提示；权限分组单列 |

### 5.2 登录

- 左侧墨黑面板陈述访问规则：功能权限、数据权限、失败码、生效时延；右侧表单。
- 表单包含用户名、密码、验证码；演示账号可一键填入。
- 提交后进入工作台，实际产品应在此调用登录接口并随后请求 `/users/me`。
- 原型不模拟 40100；真实实现收到 40100/40101 时清除 token 并跳转本页。

### 5.3 工作台

- 首屏「我的授权范围」三栏：身份事实、各模块可读/可写数量与权限来源、边界说明。
- 下方细条展示用量指标，不使用四张统计卡。
- 「可访问的 Agent」只显示当前身份可读的资源，caption 说明不可见数量。
- 「最近授权变更」需要 `system:audit_read`；无此权限时该区块改为「我的权限」，展示权限码列表与说明。
- 「快捷入口」按权限渲染；无权限的入口不出现。

### 5.4 Agent 管理

- 工具条：搜索、状态筛选、可见范围筛选；右侧显示「显示 N 条，共 M 条可访问（另有 K 条不可见）」。
- 表格列：Agent、类型、状态、归属人、可见范围、版本、成功率、最近更新、操作。
- 自己的资源行左侧有 2 px 松绿标记并带「你」标签。
- 新建按钮由 `agent:create` 控制是否渲染。
- 编辑/删除按钮同时受功能权限与数据归属控制；无权限时禁用并带原因。
- 底部分页 total 与过滤后的结果一致；注释解释「公开是可见，不是可编辑」。
- 移动端表格横向滚动，工具条提供滑动提示。

### 5.5 Agent 详情

- 页面级需要 `agent:read`；读取单条时再做数据权限判定。
- 他人私有资源：主内容替换为 40301 面板，提供「返回列表」与「切换预览身份」，不展示任何资源内容。
- 操作栏：编辑（`agent:update` + 可写）、启动/停止（`agent:start` / `agent:stop` + 可写）、发布（`agent:publish` + 可写）、删除（`agent:delete` + 可写）。
- 版本记录属于子资源，继承父资源可见性，不单独设置归属。
- 引用资源逐条显示当前身份是否可读；存在不可读引用时提示保存会失败（B-08），并说明运行时不再回溯调用者权限（4.6）。

### 5.6 用户管理

- 列表列：用户、角色、数据范围、状态、超级管理员、最近登录、操作。
- 超级管理员只能由初始化脚本设置；界面不提供任何修改入口。
- 「分配角色」弹窗展示三个角色及数据范围；保存时真实实现需校验目标角色权限是操作者权限的子集（40303）。
- 受保护账号的删除按钮禁用并说明原因：最后一个超级管理员不可删除（D-05）。
- 页面底部「保护规则」用台账表格呈现，每条对应业务码，不使用编号装饰。

### 5.7 角色管理

- 主从布局：左侧角色列表（数据范围、用户数、是否内置），右侧权限面板。
- 数据范围：全部数据 / 仅本人数据；`admin` 固定为全部数据且不可修改，权限勾选全部禁用。
- 权限按模块分组，每组提供「全选模块」等价于授予 `模块:*`；细粒度权限可单独勾选。
- 默认选中 `operator`：业务模块 4 个通配 + 模型/供应商 4 项精确 = 39 项展开权限。
- 删除仍被用户引用的角色时按钮禁用，提示 40901；`admin` 角色不可删除。
- 保存文案说明缓存失效范围：该角色下所有用户，最迟 5 分钟兜底。
- 非超级管理员操作时，页面提示「只能授予自己拥有的权限」（40303）。

### 5.8 权限管理

- 顶部细条：权限码总数、模块数、全局通配、未授予角色的预留权限数。
- 按模块分组，组头显示中文模块名与 `模块:*`；行内展示权限码、名称、覆盖接口、关联角色数、删除操作。
- 被角色引用的权限删除按钮禁用，title 显示关联角色数（40902）。
- 新建权限弹窗提供模块/动作输入与实时编码预览，前端校验格式（小写字母、数字、下划线），后端做最终校验。
- 文案明确：权限码一经创建不可修改，变更应新建并迁移。

### 5.9 审计日志

- 顶部细条：近 7 天事件、越权被拒次数、涉及角色、操作人。
- 表格列：时间、操作人、事件、目标、变更前、变更后、来源 IP；越权被拒使用印红标签。
- 审计事件不可删除、不可编辑；无法追溯到操作人的授权视为缺陷。
- 页面注明审计表为 P1：本期至少保证应用日志可检索，本页展示目标形态。

### 5.10 403 页面

- 显示请求路径、所需权限码、当前身份、数据范围、业务码。
- 两个出口：返回工作台、返回上一页；另提供切换预览身份。
- 解释为什么是 403 而不是 404；列出 40100 / 40300 / 40301 / 40302 / 40303 / 40901 / 40902 的前端行为。
- 强调前端守卫与后端功能权限使用同一套规则，直接输入 URL 与点击菜单行为一致。

## 九、设计自评与取舍

### 9.1 刻意避开

- **暖米色 + 衬线大标题 + 陶土色**：改用冷骨白、松绿与印红；宋体只出现在标题层。
- **四张统计卡 + 渐变强调**：首屏让位给授权范围台账。
- **统一圆角卡片 + 同一种柔和阴影**：表格与注记块靠规则线组织，投影只用于浮层。
- **全大写眉标、列表项之间的中点分隔、装饰性编号**：改用带标签的分段；保护规则从编号列表改为台账表格，因为规则不是序列。
- **每块内容淡入上浮**：取消入场动画，只保留回应操作的动效。

### 9.2 第一轮之后修改的地方

| 初稿 | 问题 | 修改 |
|---|---|---|
| 工作台首屏为四张统计卡 | 与授权主题无关，任何后台都适用 | 改为「我的授权范围」三栏台账 |
| 禁用按钮只靠灰色 | 用户不知道缺的是功能权限还是归属 | 增加权限注记，按业务码解释 |
| 保护规则用 01/02/03/04 编号 | 规则不是流程，编号是装饰 | 改为规则、说明、业务码三列表格 |
| 身份切换器使用「姓名 · 角色」 | 中点连接的元信息读起来像模板 | 改为「姓名 / 角色」并在菜单中分行展示角色与数据范围 |
| 权限码只出现在管理页 | 权限模型对业务页不可见 | 增加分级授权条与页面所需权限码 |

### 9.3 已知限制

- 模型、Prompt、知识库、工具等页面未绘制，菜单中标注「原型」；它们的权限码与菜单映射已在文档中定义。
- 分配角色与新建权限仅演示交互与校验规则，不写入后端。
- 数据为 mock；分页只有一页，用于展示 total 与过滤一致性。
- 未实现加载态与网络错误态；真实实现需补充骨架屏、重试与 40100 处理。

### 9.4 后续建议

1. 先落地权限上下文与路由守卫，再逐页接入按钮级权限，避免页面各自实现字符串比较。
2. 把本文档的颜色与间距 token 映射到前端现有样式体系，保留宋体标题与松绿/印红的语义。
3. 为 40301 / 40302 建立统一的错误组件，避免各页面自行拼文案。
4. 权限管理页的模块分组顺序应由后端或配置提供，不在前端硬编码。
5. 若 `viewer` 角色最终确认，再补齐其对应的审计与统计权限评审。
