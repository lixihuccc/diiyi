为什么是 403 而不是 404

内部平台优先保证可排查性

前端路由守卫与后端功能权限使用同一套规则：菜单不可见，直接输入 URL 也不可达。前端只负责呈现，最终判定始终由服务端完成（C-03 / C-07）。

不可见的数据返回 40301 而不是伪装成 404，让用户明确知道「是权限问题」而不是「数据丢了」。若未来对外开放 API，再统一切换为 404 防枚举。

业务码与前端行为

HTTP 状态码仍为 200，由 code 区分结果
code含义前端行为
40100未登录或 token 已过期清除本地 token，跳转 /login
40300缺少操作权限停留当前页，提示「无操作权限」
40301无权访问该数据停留当前页，提示「无权访问该资源」
40302非资源归属人，无法修改提示「只有创建者可修改」
40303越权授权指出具体被拒绝的权限码
40901角色仍被用户引用提示关联用户数
40902权限仍被角色引用提示关联角色数
